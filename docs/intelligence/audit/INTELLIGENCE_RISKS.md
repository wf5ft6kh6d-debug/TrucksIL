## 5. Бюджет API и инфраструктуры — оценка без запросов

Тарифы и цены **не проверялись** (запросы к провайдерам запрещены). Ниже даны объёмы, формулы и предлагаемые потолки для утверждения владельцем; это не прогноз цен.

### 5.1. Допущения объёмов (для расчёта владельцем)
- Хайфа, G1–G2: ~30–60 источников/страниц на проверку, период 1–7 суток; ~200–500 документов в месяц к обработке моделью; средний документ ≈ 10–30 тыс. входных токенов, ≈ 1–2 тыс. выходных [допущение аудитора].
- Месячный объём токенов ≈ документы × (вход + выход). Стоимость = токены × тариф провайдера [тариф не проверен].
- Firecrawl: единица учёта — кредиты за страницу/поиск; `firecrawl_search`/`scrape` биллятся по запросу, `agent` — по кредитам с `maxCredits` [по описанию инструмента, тарифы не проверены].

### 5.2. Статьи расходов

| Статья | Что определяет цену | Оценка/формула | Предлагаемый потолок для G1 (на утверждение) |
|---|---|---|---|
| Внешняя модель (извлечение/голос) | токены × тариф | см. 5.1; тариф не проверен | жёсткий дневной и месячный лимит на ключ; рекомендуется начинать с малого значения (например, порядка десятков USD/мес) и поднимать по факту |
| Firecrawl / поиск | кредиты | число страниц × кредиты/страницу | отдельный лимит кредитов в месяц; `maxCredits` на каждый запуск агента |
| VPS (кандидат Hostinger) | vCPU/RAM/диск | Для PostGIS + Valhalla (тайлы Израиля) + API ожидается класс «4 vCPU / 8–16 ГБ / 100–200 ГБ NVMe»; порядок цены — десятки USD/мес [не проверено; потребность в RAM для Valhalla Израиля по реальным данным владельца не проверена] | потолок на тариф VPS + резервные копии |
| Хранилище и бэкапы | объём сырья и копий | зависит от политики хранения (A9) | включить в лимит |
| Домены/почта/мониторинг | необязательно на G1 | — | вне G1 |
| Юридические услуги | вне технического бюджета | Заключение о приватности и лицензиях — обязательно до G1 | отдельная статья владельца |
| Внешний аудит безопасности (G4) | услуга | рынок не изучался | отдельная статья |
| Труд разработки | `INTELLIGENCE_TASKS.md`, раздел 9 | ≈180 ч-д (±50 %) | вне облачного бюджета |

### 5.3. Контроль расходов (обязательные механизмы)
Лимиты в `intel.source` и глобальный; остановка источника при превышении; запись расходов в журнал; ежедневная сводка владельцу; без авто-повышения лимитов; при исчерпании — пометка «пробел», старые данные не считаются актуальными (`SAFETY_PROTOCOL.md:5`).

## 6. Ограничения этого аудита

- Не выполнялись: e2e, миграции на PostGIS, веб smoke, запросы к внешним сервисам, открытие внешних страниц.
- Цены, тарифы, условия провайдеров и юридические нормы не проверялись.
- Не просматривалось: содержимое `web/` помимо точечных grep; `docs/research/NAVIGATORS.md` просмотрен частично; `docs/outreach/*` не читались, статус писем взят из `git log` и `DATA_SOURCES.md`.
- Подтверждены чтением: структура репозитория, ADR 0001–0019, миграции 001–005, `api/src`, схемы, названия и результаты тестов.
