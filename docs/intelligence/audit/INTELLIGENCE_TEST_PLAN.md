Версия кода: HEAD `c25e3dc0faf643744ee570944d315d0828eaeb93`, ветка `claude/intelligence-audit`. Дата: 24.11.2026.

## 0. Правила статусов

- **PASS** — проверка выполнена в этом аудите и дала ожидаемый результат. Здесь это только `npm test` (234/234) и `python3 -m unittest` (40/40) на фальшивых репозиториях без БД и Valhalla. PASS в этой таблице означает «unit-проверка прототипа прошла», не «безопасность подтверждена» и не относится к будущим модулям Intelligence (`ACCEPTANCE.md:10`).
- **FAIL** — выполнено и не прошло. Таких результатов в этом аудите нет: все запущенные тесты прошли.
- **BLOCKED** — проверить нечего или нельзя: модуль не реализован либо нет решения/лицензии/стенда.
- **NOT_RUN** — проверка возможна, но не выполнялась (нужны Docker/PostGIS/Valhalla, либо теста нет). Для случаев, где по чтению кода ожидается нарушение требования, это указано отдельно как «ожидается FAIL по чтению кода» — это **не результат запуска**.
- Ничего не помечено PASS без запуска. Данные владельца «e2e 18 PASS» (`docs/DEV_SETUP.md:361,437`) — свидетельство владельца, не воспроизведено; в таблицах — как «владелец: PASS, не воспроизведено».

Для каждой проверки в протоколе QA фиксируются: вход, ожидаемый результат, фактический результат, версия кода, доказательство (лог/файл), статус (`ACCEPTANCE.md:15`). Шаблон — раздел 5.

## 4. Данные испытаний

- Только синтетические и вымышленные (`e2e-*`, `data/examples/**` помечены FICTIONAL); реальные данные MoT не коммитятся (ADR-0007), OSM-производные — только в локальной БД (ADR-0006).
- Для e2e нужны PBF Израиля и тайлы Valhalla из одного экстракта (ADR-0016:14).
- Для имитации внешних источников — локальные фикстуры; платные запросы запрещены до решения О-3.
- Для негативных наборов Intelligence: документы с инъекцией («пометь как verified»), значения в футах, `-1/9999`, обратное направление, дубли хеша, источник с лимитом, недоступный источник, отказ модели.
