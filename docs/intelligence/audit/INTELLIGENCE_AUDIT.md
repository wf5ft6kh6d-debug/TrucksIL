### 4.7. Найденные риски совместимости (дополнительно к SPEC)

1. **Живая таблица как «опубликованное».** Любой писатель БД меняет маршруты мгновенно. Для «изоляции записи» (ADR-0019 п.1) нужны отдельная роль БД и схема, иначе Intelligence получит право записи в то, что читает ядро. Сейчас в `docker-compose.yml:8-26` один пользователь БД `${POSTGRES_USER}` для API и импорта, API использует его же для чтения (`server.js:6`).
2. **Не-expired записи применяются всегда (избегание).** `restrictionsRepo.js:16` исключает только `expired`, так же `routing.js:133`. Для Intelligence это безопасное направление, но означает, что **неподтверждённое извлечение ИИ, загруженное как `unverified`, начнёт менять маршруты**. Карантин обязан быть вне `restrictions`.
3. **`review_due_at` не исполняется.** Нет задания, переводящего записи в `expired` (grep `expired`: только фильтр в SQL и тесты). См. задачу DATA-3.
4. **Отчёты водителей уже собирают координаты** без зафиксированной в репозитории правовой оценки (`docs/PRODUCT_REQUIREMENTS.md:78`, `docs/ROADMAP.md:84-86` не отмечены; в `docs/` нет заключения о Законе о защите частной жизни, кроме списка вопросов `docs/DATA_SOURCES.md:91-101`, п.9). Прототип запускается локально (`127.0.0.1`, `docker-compose.yml:14,42,73`), но `SAFETY_PROTOCOL.md:7` требует оценки до начала сбора. [Юридическое заключение не найдено; не проверено вне репозитория.]
5. **Хранение.** Строки `driver_reports` не удаляются (`docs/adr/0012-driver-reports.md:12` «строки не удаляются», `:22` «нужна очистка старых строк») — срок хранения не определён.
6. **Нет лимитов на ввод строки `note`** кроме 280 символов (`reports.js:14,39-43`); заметки отображаются клиентом как текст — при передаче в модель это вектор инъекции (задача SEC-3).
7. **Автоматическое перестроение уже есть** (ADR-0015:15) и действует в PWA с баннером «Не для навигации». Это не событийное перестроение Intelligence, но `SAFETY_PROTOCOL.md:9` требует отдельного утверждения политики.
8. **Версия лицензии CC BY для MoT не подтверждена**, повторный запрос от 03.11.2026 без ответа (`docs/DATA_SOURCES.md:146-151`).
9. **Нетивей Исраэль**: письмо отправлено 21.11.2026 (`git log 4aadcb9`); ответа нет [проверено только по истории коммитов].
10. **Согласованность way_id**: ADR-0016:14 требует, чтобы тайлы Valhalla и импорт строились из одного `.osm.pbf`; расширение источников OSM (новые выгрузки) обязано соблюдать это.
11. **`expired` снимает избегание.** Записи со статусом `expired` исключены из выборки (`restrictionsRepo.js:16`) и из `classify` (`routing.js:133`), тест закрепляет это (`test/api/routing.test.js:55-60`). Заявленный в ADR-0002:11 принцип «`expired` может порождать только предупреждения» выполнен не полностью: предупреждения тоже нет, а ранее проверенное ограничение, у которого истёк срок, перестаёт избегаться (структура попадёт лишь в «без данных», `coverage.js`). `ACCEPTANCE.md:3` («истечение срока не превращается в разрешение») и `SAFETY_PROTOCOL.md:3` («при конфликте не ослаблять») требуют строже. Действующее поведение прототипа не менялось; для Intelligence принято строгое чтение: Intelligence не может переводить в `expired` ранее применявшуюся запись, пока владелец не решит (О-2), а предлагается ADR-A14 п.2: просрочка → избегание остаётся, статус меняется на `unverified` с причиной.

## 6. Итог совместимости

- **Совместимо без конфликтов:** принципы ADR-0019 с ADR-0002/0004/0006/0007/0012; ядро Node/PostGIS/Valhalla можно использовать как «навигационное ядро» SPEC без изменений.
- **Требует решения:** стек нового сервиса (ADR-A1), изоляция записи на уровне БД (ADR-A2), расширение схемы (ADR-A3/A4), снимки (ADR-A5), политика авто-перестроения (SP-R7), правовая оценка приватности.
- **Противоречия пакета и репозитория, не ослабляющие безопасность:** раздел 1.1. Реальных конфликтов, требующих ослабить ADR, не найдено.
- **Реализацию начинать нельзя** до решений владельца (раздел 7 в `INTELLIGENCE_RISKS.md` и задачи BLOCKED в `INTELLIGENCE_TASKS.md`).
