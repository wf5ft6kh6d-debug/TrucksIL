# Техническая концепция
## Архитектура
Источники → адаптеры сбора → карантин доказательств → проверка → версионированная PostgreSQL/PostGIS → утверждённый снимок ограничений → навигационное ядро → помощник водителя. Дорожные события идут отдельным потоком с TTL. ИИ не изменяет разрешения напрямую.

## Модули
- Research: официальные API и документы, OSM, муниципалитеты, Нетивей Исраэль; HERE/TomTom только после проверки покрытия и лицензий. Firecrawl — разрешённое извлечение документов. Повторная проверка по расписанию.
- Verification: привязка к сегменту, направлению, полосе, единицам, сроку действия; проверка происхождения и независимости источников; очередь ручного контроля.
- Traffic: аварии, пробки, ремонт, перекрытия, погода; время наблюдения, срок годности, дедупликация, конфликт источников. Просроченные сведения не считаются текущими.
- Community: запросы водителям после безопасной остановки; фото знака добровольно, без съёмки во время движения. Ответы: видел знак с указанным значением / другое значение / не видел / не знаю. Проезд и наблюдение знака — разные типы доказательств. Не направлять водителя на неизвестный проезд ради проверки.
- Route: запрос альтернативы у проверенного ядра с профилем ТС (высота, ширина, длина, масса, осевые нагрузки и применимые ограничения). Сравнение ETA, расстояния, качества данных. При отсутствии допустимой альтернативы сообщить об этом; не обещать безопасный проезд. Перестроение только по утверждённой политике и без отвлечения водителя.
- Voice: краткие предупреждения, голосовой интерфейс; некритические вопросы отложить до остановки.
- Security: защита от повторных голосов, поддельных координат, сговора, инъекций, утечек; журнал аудита.

## Модель данных (проект)
road_object: id, geometry, segment_id, direction, lane, object_type.
restriction: id, object_id, type, value, unit, conditions, valid_from, valid_until, status, version.
evidence: id, restriction_id, source_id, source_uri, observed_at, retrieved_at, hash, raw_reference, geometry, direction, observation_type, reviewer_id.
source: id, provenance, license, access_policy, reliability_class.
traffic_event: id, geometry, type, observed_at, expires_at, source_id, status.
verification_task: id, object_id, priority, status, reason.
publication: snapshot_id, approved_by, approved_at, evidence_ids, rollback_reference.

## Сила сигнала (не статус допуска)
1–4 независимых подтверждения — предварительные; 5–19 — повышенная сила сигнала; 20–99 — высокая; 100+ — массовое подтверждение. Сила сигнала не является статусом допуска и не заменяет статус verified. Это исследовательские категории, не вероятности и не разрешение проезда. Порог допуска определяется отдельным утверждённым протоколом. Критические ограничения требуют надёжного официального доказательства или квалифицированной полевой проверки. Противоречия, устаревание и неизвестные данные блокируют автоматический допуск. Хранить историю и отзыв публикаций.

## Технологии-кандидаты
Python, PostgreSQL/PostGIS, Redis для очередей, OpenAI API для анализа документов и голоса, Firecrawl, OSM. VPS Hostinger — кандидат для пилота после оценки ресурсов и безопасности. Использовать детерминированные правила для допуска; модель лишь извлекает и предлагает данные. Не обучать модель заново ради обновления базы: обновлять доказательства и записи.

## Интеграция и эксплуатация
Сначала переиспользовать Node/PostGIS/Valhalla/PWA и существующие интерфейсы после аудита; Python, Redis и внешние модели не обязательны. Исследовательский контур не имеет прав записи в опубликованные ограничения. Планировщик использует разрешённый реестр источников, лимиты, ограниченные повторы, дедупликацию и очередь ручной проверки. При исчерпании бюджета или отказе источника остановить соответствующий сбор и отметить пробел. Подробности в SAFETY_PROTOCOL.md.
