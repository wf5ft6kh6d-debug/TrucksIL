# Первая команда Codex
Прочитай весь пакет TrucksIL Intelligence. Проведи только аудит совместимости с существующим TrucksIL. Не начинай реализацию.
1. Зафиксируй HEAD, ветку, рабочее дерево и действующие ограничения. Прочитай CONTEXT.md, docs/ROADMAP.md, docs/PRODUCT_REQUIREMENTS.md, docs/DATA_SOURCES.md и все ADR 0001-0018 в docs/adr/. Не изменяй репозиторий.
2. Найди существующие схемы PostGIS, импорт ограничений, интерфейсы ядра, тесты и правила допуска. Готовое лежит здесь: db/migrations (001-005), api/src (restrictionsRepo.js, reports.js, routing.js, coverage.js), data/restrictions.schema.json, scripts/, тесты (npm test). Сопоставь с SPEC.md; не дублируй работающие компоненты.
3. Подготовь в _codex_review/ (если разрешено) INTELLIGENCE_AUDIT.md, INTELLIGENCE_ADR.md, INTELLIGENCE_TASKS.md, INTELLIGENCE_TEST_PLAN.md и INTELLIGENCE_RISKS.md. Если запись не разрешена — верни материалы текстом.
4. Раздели задачи на Research, Data, Verification, Community, Traffic, Route/Voice, Security и независимый QA. Для каждой: зависимости, исполнитель, критерии приёмки, оценка трудозатрат, блокеры.
5. Предложи бюджет API и инфраструктуры, список источников и лицензионных ограничений, изоляцию исследовательского контура. Не выполняй платные запросы и не разворачивай сервисы.
6. Верни отчёт с доказательствами, статусами и решениями, необходимыми от владельца. Остановись до утверждения. Не запускай реальную навигацию.

7. Прочитай SAFETY_PROTOCOL.md. Сопоставь каждое правило с фактическими ADR и тестами; при конфликте не ослабляй ограничения. Раздели планируемые проверки и реально выполненные проверки. Не создавай ветку, коммит или PR на этапе чтения.
8. Представь отдельные решения владельца: источники и лицензии, политика допуска, бюджет и лимиты, приватность (с учётом закона Израиля о защите приватности: основания и согласие на сбор, срок хранения, удаление, передача внешним моделям), границы пилота, разрешение записи. Без них реализация BLOCKED.
