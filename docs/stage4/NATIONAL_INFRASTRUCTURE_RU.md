# Национальный исследовательский аудит инфраструктуры и поворотов

Дата проверки: 2026-10-10. Источник — сохранённый Geofabrik Israel and Palestine от 2026-10-08, ODbL-1.0, © OpenStreetMap contributors. Этот объединённый экстракт не является юридической границей Израиля. Исходные PBF и SQLite открываются без изменения.

## Воспроизведение

```sh
python scripts/stage4/infrastructure_audit.py /tmp/trucksil-national/processed/graph.sqlite /tmp/trucksil-stage4-audit/infrastructure --sql-export --all-road-pairs
python -m unittest discover -s tests -p test_stage4_infrastructure.py -v
psql -h <isolated-unix-socket> -d trucksil_stage4_test_audit -f /tmp/trucksil-stage4-audit/infrastructure/infrastructure-check.sql
```

Последняя команда требует фактической изолированной тестовой БД. SQL сам отклоняет TCP и неподходящее имя БД. Создаёт только временные таблицы в транзакции, сверяет пары идентификаторов, DE-9IM и пять предикатов PostGIS с Shapely и выполняет rollback. Наличие SQL-файла не означает успешного исполнения; статус независимого запуска фиксирует общий отчёт QA.

## Метод и область проверки

Из 4 708 889 существующих сегментов восстанавливаются 533 306 линий исходных highway ways. Разрыв последовательности координат прерывает процесс: новый соединительный участок не создаётся. STRtree перечисляет все пересекающиеся пары исходных линий, без квадратичного перебора всех комбинаций. Режим `--all-road-pairs` исследует все дорожные ways, а не выборку и не только инфраструктуру. Предикаты в WGS84 используются для топологических отношений без вывода метрических расстояний.

JSONL содержит каждую пару: OSM IDs, версии, DE-9IM, intersects/touches/crosses/overlaps/equals, общие ID узлов и статус UNKNOWN. Для обычных касаний общими узлами запись компактная; исходные теги доступны по ID в неизменённой базе. Для сложных случаев и инфраструктуры сохранены также теги и геометрия пересечения. Совпадение идентификатора где-то на двух ways не означает, что **каждое** их геометрическое пересечение имеет общий узел. Эти случаи не превращаются автоматически в физические соединения.

Файл `infrastructure-ways.jsonl` содержит все активные bridge/tunnel highway ways, теги, версию, timestamp, геометрию и оба конца way. Координата конца way — предполагаемый конец картографической линии, а не независимо подтверждённый физический портал. Общие OSM node ID отражают картографическую связность, но не подтверждают высотный уровень или допуск грузовиков. `bridge=no/false/0` и `tunnel=no/false/0` не считаются активной инфраструктурой.

## Повороты

Проверены все 14 463 отношения, сохранены исходные роли, tags, версии и отсутствующие ссылки. Для единственных from/via-node/to проверяется наличие via в обоих ways и возможность подхода/выезда по явно указанному oneway. Отсутствующее oneway остаётся unknown; геометрия, roundabout и класс дороги не подставляют значение.

Via-way, множественные роли, conditional, except и vehicle-specific restrictions требуют отдельной семантической проверки. Выявленный конфликт явного направления является кандидатом, а не доказательством действующего дорожного запрета или ошибки OSM. Все отношения остаются QUARANTINE, включая простые структурно согласованные.

## Ограничения интерпретации

Ни одна геометрическая проверка не даёт высоту тоннеля, грузоподъёмность моста, разрешение HGV или статус verified. Разные сырые значения layer дают кандидата на разные уровни, но не подтверждённую отметку высоты. Нет независимо подтверждённых физических порталов, соединений или грузовых ограничений. Входной граф и исходный пилот Хайфы не изменялись.

Машиночитаемые результаты и SHA-256 больших JSONL: `data/stage4/infrastructure-summary.json`. Полные JSONL и SQL находятся в воспроизводимом артефакте аудита вне Git. На момент подготовки модуля 11 регрессионных тестов исполнены успешно; они используют только тестовые фикстуры, не искусственные дорожные данные.
