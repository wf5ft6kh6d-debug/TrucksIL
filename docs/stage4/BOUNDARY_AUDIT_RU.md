# Аудит границы экстракта и отсутствующего участника OSM

Дата исследования: 2026-10-10. Исходный PBF не изменён. Полигон Geofabrik описывает границу экстракта **Israel and Palestine**, а не официальную государственную границу. Ни один объект автоматически не удалён и не добавлен в граф.

## Полный геометрический результат

Проверены все 4 708 889 сегментов; 14 407 имеют середину вне полигона. Они принадлежат 542 ways.

| Наблюдение | Сегменты |
|---|---:|
| Сегмент полностью снаружи; полная родительская way пересекает полигон | 14 085 |
| Сам сегмент пересекает границу, середина снаружи | 322 |
| Вся родительская way вне полигона | 0 |

Это доказанные геометрические отношения, совместимые с сохранением полной геометрии пограничных ways. Конкретный алгоритм отбора экспортёра не доказан, поэтому **cause_status=UNKNOWN**, состояние объектов **QUARANTINE**. `geometry_observation_status=VERIFIED` относится исключительно к вычисленному геометрическому факту, а не официальным уровням, транспортному допуску или государственной принадлежности.

Полный реестр `outside-segments.jsonl` содержит для каждой строки ID сегмента/way/node, версию и timestamp way, координаты обоих концов и середины WGS84, исходные теги, DE-9IM и классификацию. SHA-256 реестра:

`b32a847a2b9e69f530601a0d5d35d18cd177c481f94e04b72c580788d238669c`

Никакие соединения на границе не создаются. Классификация страны/юрисдикции остаётся вне этого аудита.

## Воспроизводимость и тесты

```bash
PYTHONPATH=/tmp/trucksil-stage4-deps python scripts/stage4/boundary_audit.py \
  --database /tmp/trucksil-national/processed/graph.sqlite \
  --boundary data/stage4/source-boundary.poly \
  --output /tmp/trucksil-stage4-audit/boundary
PYTHONPATH=/tmp/trucksil-stage4-deps python -m unittest discover -s tests -p test_stage4_boundary.py -v
```

Полный запуск: 15.245 секунды; **8/8 тестов PASS**. Каталог вывода должен быть новым: существующий реестр не перезаписывается. Синтетические примеры используются только в тестах.

Стандартный CLI автоматически вызывает `export_postgis(database,boundary,registry,output)` и создаёт `boundary-postgis.sql`: все 14 407 случаев, 542 полные родительские геометрии и исходный полигон; сравниваются ST_Covers, ST_Intersects, ST_Crosses, ST_Touches и ST_Relate с Python. Только временные таблицы, Unix socket и БД `trucksil_stage4_test_*`, итоговый ROLLBACK. Результат фактического выполнения PostGIS фиксируется общим независимым отчётом; наличие SQL-файла само по себе не означает PASS.

## Следующее действие

Сохранить пограничные сегменты в исследовательском оригинале. Для производного автомобильного слоя явно задавать область отбора и сохранять пограничные разрывы как классификацию, не как повод соединять линии. Проверять согласованность полного turn-restriction и правила включения внешних участников экстракта, прежде чем рассматривать восстановление данных; действующее правовое ограничение этим не подтверждается.

Дополнительная проверка версий узлов после первоначального реестра сохранена отдельно: `docs/stage4/evidence/boundary-snapshot-proof.json`. Первоначальный `data/stage4/boundary-osm-evidence.json` сохраняет результат первого исследования; дополнение подтверждает координаты на дату снимка и не меняет входные дорожные данные.
