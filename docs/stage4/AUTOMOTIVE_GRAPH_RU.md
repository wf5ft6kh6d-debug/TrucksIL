# Производный автомобильный исследовательский граф

Дата проверки: 2026-10-10. Политика `automotive-research-v1`.

Это отдельный слой отбора автомобильных кандидатов, не разрешение движения автомобиля или грузовика. Исходный PBF и исследовательская SQLite-база не изменяются. Геометрия не обрезается, узлы не создаются, направления не выводятся из класса дороги. Отношения поворотов исходника остаются в карантине и не применяются как проверенные маршрутные правила.

## Правила

`INCLUDED` означает пригодность класса объекта для дальнейшего автомобильного исследования. Отсутствующий access получает `access_status=UNKNOWN`; отсутствие грузового запрета не является разрешением. `truck_access=UNKNOWN`, `independently_verified=false` для каждой записи.

1. `area=yes` исключается из осевых линий независимо от access. Неизвестный area требует карантина.
2. `construction/proposed/abandoned/razed` исключаются как неактуальный дорожный класс. Lifecycle-префиксы на других дорогах требуют проверки.
3. `footway/pedestrian/cycleway/steps/bridleway/corridor/platform` исключаются; явное разрешение транспортного режима либо scoped-тег отправляет такую комбинацию в карантин, не превращая пешеходную геометрию в автомобильную.
4. Кандидаты: `motorway`, `trunk`, `primary`, `secondary`, `tertiary` и их `_link`; `unclassified/residential/living_street/service`.
5. Все другие классы, включая `track/path/road/busway/raceway`, остаются в карантине. Это консервативное правило исследования, не утверждение их фактической непроезжести.
6. Для легкового режима выбран приоритет `motorcar > motor_vehicle > vehicle > access`. Он не переносится на грузовики. Значения `yes/designated/permissive` сохраняются как заявленная тегом доступность; `no/private` исключают объект из общего автомобильного слоя; ограниченные цели (`destination/delivery/customers` и другие) либо неизвестные значения требуют карантина. Особый случай: **`access=designated` без транспортного режима не определяет доступность**, поэтому UNKNOWN/QUARANTINE.
7. Scoped/conditional-теги access требуют карантина. HGV и HGV:conditional сохраняются отдельно в `decision.hgv_tags`, не изменяя автомобильную классификацию и не получая VERIFIED.
8. Scoped oneway, reversible/alternating и неизвестные значения требуют карантина. Исходное направление каждого сегмента сохраняется буквально, включая UNKNOWN. Не применяются подразумеваемые правила motorway/roundabout.

Официальная документация сообщества OSM проверена 2026-10-10: [access](https://wiki.openstreetmap.org/wiki/Key:access), [motorcar](https://wiki.openstreetmap.org/wiki/Key:motorcar), [hgv](https://wiki.openstreetmap.org/wiki/Key:hgv). Это описание тегов, не независимое свидетельство израильского дорожного приказа. Никакие закрытые или коммерческие данные не получены.

## Структура и воспроизводимость

```bash
python scripts/stage4/automotive_graph.py \
  /tmp/trucksil-national/processed/graph.sqlite \
  /tmp/trucksil-stage4-audit/automotive \
  --manifest data/stage4/national-source-manifest.json
python -m unittest discover -s tests -p test_stage4_automotive.py -v
```

Используется только стандартная библиотека Python. Новая директория обязательна: существующий результат не перезаписывается. Исходник присоединён SQLite URI `mode=ro`.

`automotive.sqlite` сохраняет полные исходные таблицы nodes/segments и все исходные колонки ways; ways дополнена status/reason/decision. Представления `automotive_segments`, `automotive_nodes`, `quarantine_segments`, `excluded_segments` строго разделяют выборки. Не следует использовать таблицу segments целиком как автомобильный граф. Исходные кандидаты/relations остаются в исследовательском оригинале, их состояние не изменено. В metadata сохранены источник, лицензия ODbL-1.0, атрибуция © OpenStreetMap contributors и SHA-256.

База производного слоя не является миграцией существующей эксплуатационной схемы. Крупный SQLite-файл хранится вне Git, малая сводка — `data/stage4/automotive-summary.json`.

Скрипт проверяет полное двустороннее EXCEPT-сравнение всех исходных строк ways/nodes/segments, FK, quick_check и SHA-256 источника до/после. Регрессионные тесты проверяют классы, приоритет access, отсутствие разрешения при пропусках, HGV, conditional, направления, area/lifecycle, запрет перезаписи, детерминированный повторный SQLite и неизменность источника. Синтетические объекты используются только в тестах.

Первичная проверка выявила ошибочную обработку общего `access=designated`; сначала добавлен воспроизводящий падающий тест, затем исправлен классификатор. Исходные OSM-теги не изменены.

## Ограничения

Классификация учитывает теги ways; барьеры и ограничения на отдельных nodes ещё не применяются как ограничения прохода графа. Политика не оценивает физическую ширину, покрытие, проходимость, габариты сооружений и юридическую действительность OSM-тегов. Грузовые направления и права доступа не подтверждены. Наличие INCLUDED не заменяет дальнейший топологический, инфраструктурный и официальный аудит.
