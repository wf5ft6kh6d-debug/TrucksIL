## Офлайн-процесс

```
python -m unittest discover -s tests -v
python scripts/compare_schema_engine.py
python scripts/stage3/build_pilot.py --output /tmp/trucksil-pilot-new
python src/ingest_restrictions.py /tmp/trucksil-pilot-new/restrictions.json --as-of 2026-10-10T10:00:00Z
```

Выходная директория должна отсутствовать. Полный checksum/размер, разрешение
ODbL, CRS, source revision, типы, версии, координаты и ссылки проверяются до
выдачи результата. Summary и digest нормализованных данных сверяются с
`expected-summary.json`. Формат digest: canonical JSON списка nodes, segments,
observations, relations, ключи отсортированы, UTF-8, без пробелов.

Существующая схема геометрии TrucksIL применяется к точкам/линиям. Дорожные
линии разбиваются по каждой паре последовательных OSM-узлов; соединение только
по исходным ID, никогда по пересечению линий или совпадению координат. Сохраняются
way/node ID, версия, время редактирования, теги и общий checksum среза. Общая
ревизия нужна контракту stage2: узлы и сегменты одного снимка имеют одну ревизию;
индивидуальные версии не теряются. Топология остаётся unverified.

В граф попадают только перечисленные в коде дорожные классы, без площадных
объектов. Исключены стройка, пешеходные линии, ступени и track; это намеренно
неполная исследовательская выборка. Пара узлов включается только если оба внутри
прямоугольника; координаты не обрезаются и новые точки не придумываются.
Полные исходные ways могут выходить за окно. Пересечения без узла не соединяются;
layer/bridge/tunnel сохраняются, но физическая связь конструкций не подтверждается.

## Ограничения — отдельный карантин

Все исходные access/vehicle/motor_vehicle/oneway, грузовые и условные теги
сохраняются как unverified observations. Отношения поворотов сохраняются отдельно,
включая исходных участников и роли; 6 ссылок на участников вне выгрузки не разрешены.
Они не превращаются в исполнимые ограничения. 504 наблюдения включают обычные
направления движения; это НЕ 504 грузовых запрета.

Декодер поддерживает только положительные десятичные m/t и перевод kg в t;
число без единицы трактуется по документированному OSM-контракту. Неизвестные
единицы, imperial, специальные значения и условия остаются неразобранными.
`forward/backward` относятся к порядку OSM way, а не сторонам света. Отсутствие
направления не становится both; условная one-way не становится постоянной.
Документация семантики: https://wiki.openstreetmap.org/wiki/Key:maxheight,
https://wiki.openstreetmap.org/wiki/Key:maxweight,
https://wiki.openstreetmap.org/wiki/Key:hgv,
https://wiki.openstreetmap.org/wiki/Key:oneway.

Дата редактирования OSM не равна observedAt. Без фактического наблюдения,
актуальной применимости и предусмотренной проверки schema-record ограничения
не создаётся. `restrictions.json` сейчас `[]`; существующий валидатор подтверждает
пустой пакет со статусом unknown/false. Неполные observations им отвергаются.
Никакие данные не записываются в закрытый restriction_staging, триггер не отключён.

## Изолированный PostGIS

CI сохраняет все проверки этапа 2 и выполняет `pilot-replay.sql` после миграций
в одноразовой `trucksil_stage2_test_hardening` через Unix socket. SQL требует
пустых staging-таблиц, загружает реальные узлы/сегменты в существующую схему,
проверяет геометрию, bbox, endpoints, source revision, аудит, отсутствие
ограничений и unknown safety. Длины независимо пересчитываются PostGIS;
сферическая сумма сверяется с Python с допуском 1 метр на весь граф.
Транзакция ВСЕГДА ROLLBACK; отдельное соединение проверяет отсутствие строк.
Это проверка совместимости, не миграция реальных существующих данных.
30-дневный срок повторной проверки лицензии — внутренняя политика пилота,
не срок действия ODbL. Миграции этапа 2 и production не меняются.
