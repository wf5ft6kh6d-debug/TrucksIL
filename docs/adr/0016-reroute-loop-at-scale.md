# ADR-0016: Цикл перестроения при реальных данных (сопоставление по way, предисключение, лимиты Valhalla)

- **Статус:** Принято
- **Дата:** 2026-11-21
- **Дополняет:** ADR-0011 (лимит перестроений 3 заменён, ступени исключения сохранены)

## Контекст
После импорта 1034 OSM-кандидатов (PR #16) маршрут Тель-Авив → Иерусалим давал 8 объездов и 2 перестроения, e2e — 11 FAIL (лишние перестроения, `422` Хайфа → Тель-Авив, `409` S12b/S12c). Причины:
1. **Совпадение только по расстоянию.** Все 8 «объездов» — `osm-maxheight-way*`, по которым маршрут не едет (жилой тоннель, подземная парковка `service=parking_aisle` в пределах 50 м). Точки `-crossing` лежат и на мосту над дорогой, поэтому маршрут **по мосту** получал конфликт с проездом **под** ним.
2. **Цикл реактивный и короткий:** каждый новый маршрут открывает новые конфликты, 3 попыток мало.
3. **Лимит Valhalla на `exclude_polygons`:** `service_limits.max_exclude_polygons_length` — «Maximum total perimeter of all exclude_polygons in meters», по умолчанию **10000** (`scripts/valhalla_build_config` в valhalla/valhalla); превышение — ошибка **167** «Exceeded maximum circumference for exclude_polygons», HTTP 400 (`valhalla/exceptions.h`). Узкое исключение (±30 м × ±7 м) — ~180 м периметра, т. е. ~50 конфликтов исчерпывают лимит; ошибка 400 раньше превращалась в ложный `422`. Ограничения на число многоугольников нет — только суммарный периметр.

## Решение
- **Сопоставление по way (`ROUTE_WAY_MATCH`, по умолчанию вкл.).** Для записей с `road_segment_id = osm:way:<id>`, которые являются линией этого way или точкой `-crossing<bridge>`, ограничение применяется (и попадает в `onRoute`), только если `<id>` есть среди `edge.way_id` маршрута из Valhalla `/trace_attributes` (тот же запрос, что в ADR-0014; один вызов на итерацию и только если рядом есть такие записи; в API запоминается, финальный маршрут не трассируется дважды). Ошибка trace → сопоставление не применяется (консервативно, ADR-0002). Узлы `osm-maxheight-node*` и записи без OSM way (ручные, Минтранс) — по-прежнему по расстоянию: узел может принадлежать нескольким way. Предпосылка: тайлы Valhalla и импорт построены из одного `.osm.pbf` (иначе way id могут разойтись) — при сомнении `ROUTE_WAY_MATCH=0`.
- **Накопление и лимит.** Исключения копятся по всем итерациям (ничего не снимается); лимит `MAX_REROUTES` (по умолчанию 8).
- **Предисключение (`PRE_EXCLUDE`, по умолчанию вкл.).** После первого конфликтного маршрута — один запрос к PostGIS: конфликты в 3 км от маршрута, кроме уже исключаемых; они исключаются сразу компактными квадратами 6 м (точка — один, линия — два, на 15 % и 85 % длины, чтобы не задеть мост над серединой). Пропускаются точки `-crossing` (квадрат вырезал бы дорогу на мосту) и направленные записи. Ближайшие — первыми, не более `MAX_PRE_EXCLUSIONS` (200) и в пределах остатка бюджета периметра. Предисключения «мягкие»: если с ними Valhalla не находит маршрут, они снимаются и цикл продолжается реактивно; в `avoided` попадают только конфликты, реально встреченные на маршрутах.
- **Бюджет периметра:** `VALHALLA_MAX_EXCLUDE_PERIMETER_M` (по умолчанию 10000, используется 95 %). Обязательные исключения сначала; при нехватке новые узкие кольца сжимаются до ±8 м; если обязательные всё равно не помещаются — `409` с явной причиной. Ошибка 167 от Valhalla → `409` «perimeter limit», а не `422`.
- **Безопасность не меняется:** маршрут возвращается только без известных конфликтов; `409`/`422` — как раньше. `422` дополнительно содержит `blockingCandidates` — исключения, добавленные на последнем шаге (до него маршрут существовал), и `exclusions` (id, ступень).
- **Диагностика:** `POST /v1/route?debug=1` (или заголовок `x-trucksil-debug: 1`) → `trucksil.debug` (или `debug` в теле ошибки): конфигурация и по итерациям — конфликты (id, тип, значение, статус, причина, источник, URL OSM), отброшенные по way (`otherRoad`), предисключения, число колец и периметр. `scripts/explain_route.js` печатает это со ссылками OSM.
- **e2e относительно базового маршрута** (`scripts/e2e_routes.js`, `evaluateRelative` в `test/scenarios/lib.js`): базовый не 200 → SKIP «baseline blocked by non-test data»; для объездов `reroutes ≥ max(minReroutes, базовые)`, для сценариев без объезда — засеянный id не в `avoided`, статус 200; отличие числа перестроений от базового — примечание. `E2E_STRICT=1` — прежняя абсолютная проверка.

## Последствия
- Ложные объезды из-за соседних тоннелей/парковок и проездов под мостом, по которому едет маршрут, исчезают — при условии одинаковой выгрузки OSM для Valhalla и импорта.
- Предисключение может удлинить маршрут (квадрат задевает примыкающие рёбра) — компенсируется мягким снятием; параметры (3 км, 6 м, 15/85 %) не проверены на реальных данных.
- Импорт по-прежнему загружает `service=parking_aisle/driveway`; по way они на маршрут грузовика почти не попадут, фильтр в импорте — отдельная задача.
