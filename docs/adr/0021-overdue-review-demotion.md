# ADR-0021: Просроченная проверка понижает `verified` до `unverified`, а не до `expired`

- **Статус:** Принято
- **Дата:** 2026-11-24

## Контекст
У записи есть `review_due_at` (срок пересмотра), но ничто его не исполняло: проверенное ограничение с истёкшим сроком оставалось `verified` навсегда (аудит, п. 7 и задача DATA-3). Перевод в `expired` опасен: `expired` не заставляет объезжать участок, а только предупреждает (ADR-0002, ADR-0020), то есть ранее проверенный низкий мост перестал бы избегаться из-за формальной просрочки.

## Решение
1. `verified` с `review_due_at` в прошлом считается `unverified`: ограничение по-прежнему избегается (ADR-0002), но не учитывается как проверенное.
2. **Чтение:** запросы маршрутизации возвращают такую запись как `unverified` сразу, без ожидания фонового задания (`restrictionsRepo.js`); покрытие тоннелей и подземных переездов не считает её проверенной (`underpassesRepo.js`).
3. **Запись:** `scripts/demote_overdue_reviews.js` (`api/src/reviewDue.js`) по расписанию переводит такие записи в `unverified`. По умолчанию это пробный запуск, запись только с `--apply`. Изменение идёт одной транзакцией через журнал аудита с актором `system:review-due`; `verified_by` и `verified_at` сохраняются как история.
4. `expired` автоматически не выставляется никогда: его ставит только человек или отдельное решение.

## Последствия
- Просрочка больше не даёт ложного «проверено».
- Повторную проверку записи делает модератор: она вернёт `verified` с новым `review_due_at`.
- Нужно настроить периодический запуск скрипта (cron) там, где развёрнута база; без него работает только защита при чтении.
- Не проверено на реальной PostGIS: SQL проверен тестами на фальшивой базе.
