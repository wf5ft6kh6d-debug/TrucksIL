# ADR-0012: Сообщения водителей — отдельно от официальных данных

- **Статус:** Принято
- **Дата:** 2026-11-15

## Контекст
US-05 требует, чтобы водители могли сообщать о пробках, авариях, опасностях, камерах и низких габаритах. При этом ADR-0002 и `docs/DATA_VERIFICATION.md` запрещают пользовательскому сообщению самому по себе становиться официальным ограничением, а US-08 требует не собирать персональные данные и историю перемещений.

## Решение
1. **Отдельное хранилище.** Таблица `driver_reports` (миграция `002_driver_reports.sql`) не связана с `restrictions` ни внешним ключом, ни представлением. Сообщения не участвуют в проверке маршрута (`routing.js` о них не знает); в ответ `/v1/route` они добавляются уже после `planRoute` в поле `trucksil.reports` (в пределах 100 м от итогового маршрута) только для информации. Ошибка поиска сообщений даёт `trucksil.reports: null` и не блокирует маршрут.
2. **Маркировка.** Каждое сообщение в API несёт `verified: false`, `label: "unverified driver report"`; в интерфейсе — отдельный слой и значок «דיווח נהג, לא מאומת» / «driver report, unverified» на всех четырёх языках. Перевод сообщения в официальное ограничение возможен только через обычную процедуру проверки (`DATA_VERIFICATION.md`) с новым источником, а не автоматически.
3. **Время жизни по типу:** traffic 1 ч, accident 3 ч, hazard 12 ч, camera 30 сут, low_clearance 30 сут, other 6 ч. Просроченные не отдаются (`expires_at > now()` в запросе); строки не удаляются.
4. **Анонимность.** Клиент генерирует случайный id и хранит его в `localStorage`; отправляет в заголовке `x-trucksil-client`. Сервер хранит только HMAC-SHA256(id, `REPORTS_SALT`). Нет учётных записей, IP не сохраняется, координаты есть только у самого сообщения (не трек). Без `REPORTS_SALT` используется dev-соль с предупреждением в логе.
5. **Защита от злоупотреблений.** Не более 5 сообщений за 10 минут на хеш клиента (в памяти процесса). Один голос (`confirm`/`reject`) на клиента на сообщение (`driver_report_votes`). Автоскрытие, если отклонений ≥ 3 и больше подтверждений.
6. **Модерация.** `POST /v1/reports/:id/moderate {action: hide|show}` с заголовком `x-moderator-token`, равным `MODERATOR_TOKEN`; если токен не задан — всегда 403. Все действия (включая автоскрытие) пишутся в `report_moderation`, которая только для добавления (триггер запрещает UPDATE/DELETE).
7. **Прототип:** новые сообщения сразу получают статус `visible` (статус `pending` зарезервирован для будущей премодерации).

## Последствия
- Водитель видит свежие сообщения, но они никогда не делают маршрут «безопаснее» и не скрывают официальные ограничения.
- Ограничение частоты в памяти сбрасывается при перезапуске и не работает между несколькими экземплярами API — для продакшена нужен общий счётчик (Redis/БД).
- Анонимный id можно сбросить очисткой хранилища браузера; защита от накрутки голосов слабая, это осознанный компромисс прототипа.
- Нужны: интерфейс модератора, очистка старых строк по сроку хранения, вычитка переводов he/ar носителем.
