# ADR-0014: Честное покрытие маршрута — мосты и тоннели «без данных»

- **Статус:** Принято
- **Дата:** 2026-11-21

## Контекст
ADR-0002 и US-03 требуют показывать, где у TrucksIL нет данных, а не только где есть ограничения. До сих пор ответ `/v1/route` содержал заглушку `trucksil.unverifiedCoverage: "unknown"`. По `docs/OSM_COVERAGE.md` клиренс известен лишь для ~16,5 % проездов под мостами, поэтому «на маршруте ограничений нет» почти всегда означает «данных нет». Рекомендация 3 из `docs/research/NAVIGATORS.md` — явно помечать участки без данных.

## Решение
1. **Что считаем.** «Сооружение» — мост или тоннель на итоговом маршруте. Оно «с данными», если в пределах 30 м от его геометрии есть любое ограничение TrucksIL (проверенное или нет; `expired` не учитывается — так работает `repo.findAlongRoute`). Иначе — «без данных».
2. **Источник сооружений — Valhalla, без нового набора данных.** После `planRoute` API вызывает `POST /trace_attributes` с формой маршрута (`encoded_polyline`, точность 6, `shape_match: "edge_walk"`, `costing: "truck"`) и фильтром атрибутов `edge.bridge`, `edge.tunnel`, `edge.way_id`, `edge.begin_shape_index`, `edge.end_shape_index`, `shape` ([документация Valhalla, Map Matching API](https://valhalla.github.io/valhalla/api/map-matching/api-reference/)). Подряд идущие рёбра одного типа, смежные вдоль маршрута (конец ребра = начало следующего по индексу формы или разрыв < 20 м), объединяются в одно сооружение независимо от `way_id`; список OSM way сохраняется в `wayIds` (`wayId` — первый, для совместимости). Код — `api/src/coverage.js`.
3. **Ответ.** `trucksil.coverage` дополняется полями `status` (`"computed"` | `"unknown"`), `structuresOnRoute`, `structuresWithData`, `noDataSegments: [{type, from, to, wayId, coordinates}]`, `limits`; поля `verifiedOnRoute`, `unverifiedOnRoute`, `note` сохраняются. Заглушка `unverifiedCoverage` из успешного ответа убрана (в ответах-ошибках она пока остаётся в `TRUCKSIL_NOTICE`).
4. **Отказ = неизвестно.** Любая ошибка (`trace_attributes` недоступен, нет `edges`, неверные индексы, ошибка БД) даёт `status: "unknown"` и `null` в счётчиках. Значения «ok»/«безопасно» нет вообще; `"computed"` означает лишь «подсчитано». Маршрут при этом не блокируется: покрытие — информация, а не проверка.
5. **Интерфейс.** Участки без данных рисуются пунктиром янтарного цвета поверх маршрута с подписью-легендой; в панели строка «Мостов/тоннелей на маршруте: N, с данными TrucksIL: M — N−M без данных (проверьте знаки)» на всех 4 языках; при `unknown` — «не определено … проверьте знаки».

## Последствия
- Водитель видит, сколько сооружений на маршруте не покрыты данными, без дополнительной загрузки OSM.
- **Ограничение (частично снято):** дорога, проходящая ПОД мостом, в рёбрах Valhalla не помечена.

## Дальнейшие шаги — сделано (21.11.2026)
- **Объединение смежных сооружений** (см. п. 2): на Тель-Авив → Иерусалим соседние тоннели из разных OSM way больше не считаются по отдельности.
- **Проезды под мостами.** Миграция `db/migrations/004_route_structures.sql` — таблица `osm_underpasses` (точка пересечения дороги и моста, `osm_road_way_id`, `osm_bridge_way_id`, `bridge_kind` road|rail, `road_ref`, `road_class`, `osm_maxheight_text/_m`, `loaded_at`, `source_extract_date`; GiST-индекс). Заполняет `scripts/load_osm_underpasses.py` (импортирует помощники `scripts/osm_bridge_clearance.py`; TRUNCATE + COPY в одной транзакции через `psql`, без Python-драйвера БД). Данные производные от OSM (ODbL) и живут только в локальной БД, в репозиторий не коммитятся.
- **Сопоставление только по way id.** Проезд считается «на маршруте», если его `osm_road_way_id` входит в `way_id` рёбер маршрута из `trace_attributes` И точка пересечения ближе 15 м к линии маршрута. Поиск только по расстоянию недопустим: он поймал бы мосты, по которым маршрут едет сверху. Проезд «с данными», если в 30 м от точки есть ограничение TrucksIL `max_height` (любой статус, кроме `expired`).
- **Ответ** (`trucksil.coverage`, обратно совместимо — только новые поля): `underpassStatus` (`"computed"` | `"not_loaded"` — таблицы нет или она пуста | `"unknown"` — ошибка), `underpassesOnRoute`, `underpassesWithData`, `noDataUnderpasses: [{point, roadRef, osmMaxheightCandidate: {text, metres, note} | null}]`. При `not_loaded`/`unknown` счётчики `null`, а не 0. `noDataSegments[]` получили `wayIds`. Значение `maxheight` из OSM — только «кандидат OSM» для показа, в решениях маршрутизации не используется.
- Отображение проездов в веб-интерфейсе — отдельная задача.
- Лишний запрос к Valhalla на каждый маршрут (+ по одному запросу к БД на сооружение).
- Формат ответа `trace_attributes` проверен только по документации и моку; нужна проверка на настоящей Valhalla 3.9.
