# ADR-0011: Направление ограничений и точное исключение участка

- **Статус:** Принято
- **Дата:** 2026-11-15

## Контекст
Ограничения TrucksIL применяются к маршруту Valhalla после его построения (ADR-0009): ищутся записи в 50 м от линии, конфликт исключается через `exclude_polygons` (многоугольник 20 м вокруг ограничения), маршрут перестраивается. Две проблемы прототипа:

1. Поле `direction` (`both`/`forward`/`backward` относительно порядка оцифровки геометрии, `data/restrictions.schema.json`) игнорировалось: ограничение одной проезжей части (например, мост только над полосой на север) уводило с маршрута и встречный поток.
2. Круг 20 м вокруг ограничения на развязке или разделённой трассе задевает встречную проезжую часть и пересекающие дороги, из-за чего объезд получается лишним, длинным или невозможным (`422`).

## Решение
- **Направление.** Для ограничения-линии с `forward`/`backward` сравниваются азимут маршрута (отрезок ±15 м вокруг ближайшей к линии точки) и азимут участка линии в этой точке. Расхождение ≤ 60° — проезд по направлению оцифровки (`forward` применяется), ≥ 120° — против (`backward` применяется); иначе (в т. ч. пересекающая под прямым углом дорога) ограничение для этого маршрута не действует. Точки, `both`, отсутствие геометрии, вырожденная линия, маршрут короче 5 м у точки — ограничение **применяется** (консервативно, ADR-0002).
- **Точное исключение, ступенчато для каждого конфликта:**
  1. узкие прямоугольники вокруг **участка маршрута**, проходящего у ограничения: подлиния ±30 м от ближайшей точки, полуширина 7 м (по прямоугольнику на каждый отрезок упрощённой подлинии, с запасом 7 м на концах, чтобы перекрываться на изгибах);
  2. если следующий маршрут снова конфликтует с тем же ограничением — добавляется прежний многоугольник 20 м вокруг самого ограничения (`ST_Buffer` по geography в PostGIS);
  3. если не помогло и это — `409` («exclusion had no effect»); общий лимит — 3 перестроения. Без геометрии сразу используется ступень 2.
- **Где считается геометрия — в JS (`api/src/routeGeometry.js`), а не в PostGIS.** Обе операции работают с линией маршрута, которая уже декодирована в памяти API; в базе её нет, её пришлось бы передавать в каждый запрос. Нужна только локальная геометрия в окрестности ~100 м (равнопромежуточная проекция вокруг широты ограничения, ошибка — доли метра), без индексов. Так логика проверяется модульными тестами без Docker и не добавляет запросов к БД. Поиск ограничений вдоль маршрута и «широкий» многоугольник 20 м остаются в PostGIS.

## Последствия
- Направленные ограничения, внесённые линией по своей проезжей части, больше не влияют на встречную; точечные по-прежнему действуют в обе стороны — для одностороннего ограничения нужна линия.
- Узкий прямоугольник плоский: дорога, пересекающая маршрут ровно в месте ограничения (под/над мостом), тоже исключается — у `exclude_polygons` нет уровней. Это консервативно; при необходимости escalation до 20 м остаётся.
- Обнаружение «на маршруте» осталось в радиусе 50 м, поэтому точечное ограничение на соседней параллельной дороге может дать конфликт; ступенчатое исключение уменьшает лишние объезды, но не устраняет такое срабатывание.
- Параметры (15 м, 5 м, 60°, ±30 м, 7 м) подобраны без проверки на реальных данных; поведение на настоящей Valhalla (что узкий прямоугольник действительно исключает ребро, включая короткие рёбра целиком внутри него) нужно подтвердить e2e-прогоном (сценарии S11a–S11d) на машине владельца.
