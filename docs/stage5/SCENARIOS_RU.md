# Исследовательские сценарии и связность — этап 5

## Назначение и пределы

Модуль `scripts/stage5/scenarios.py` не выдаёт разрешение на движение. Во всех
результатах `navigation_eligible=false`; ни один источник не становится VERIFIED.
Оригинальная SQLite открывается `mode=ro`; её SHA-256 сравнивается до/после.
Не создаются соединения по пересечениям геометрий, snapping или новые сегменты.

Национальная область сравнения — только INCLUDED неизменённого классификатора
этапа 4. EXCLUDED и QUARANTINE подсчитываются отдельно. Это существенное ограничение:
дорога, исключённая автомобильной политикой этапа 4, не восстанавливается даже при
новом HGV-теге. Приведённые числа не описывают полную грузовую сеть.

## Метрики и эксперименты

Сохраняется одинаковое множество исходных вершин для всех экспериментов; удаление
условного ребра не скрывает оставшиеся изолированные узлы. Подсчитываются:

- слабые компоненты геометрической топологии, включая UNKNOWN-направления;
- слабые компоненты графа только явно известных направлений;
- количество направленных дуг и исходные категории направлений;
- направленная достижимость из трёх фиксированных OSM-узлов с наибольшим числом
  инцидентных сегментов; при равенстве выбирается меньший ID.

Это три полных BFS, не все пары и не вычисление сильно связных компонент.
Неизвестное направление не подменяется двусторонним движением. Разница компонент
между топологией и направленным подграфом отражает исключение неизвестных направлений,
а не доказанный физический разрыв.

Сравниваются baseline, гипотетическое исключение TAGGED_DENIED и более консервативное
исключение TAGGED_DENIED вместе с UNKNOWN. Это анализ чувствительности к непроверенным
тегам, а не принятие ограничения для эксплуатации. Положительный тег не добавляет
дугу и не восстанавливает исключённую дорогу. Направленный запрет на way удаляет
только соответствующую дугу; узловые правила применяются к инцидентным сегментам.
UNKNOWN остаётся неопределённостью даже там, где baseline сохраняет ребро.

Для temporal records добавлены две явно заданные исследовательские даты:
`2026-10-12T07:00:00+03:00` и `2026-10-12T09:00:00+03:00`, Asia/Jerusalem.
Применяется только deny-only поднабор `access/vehicle/motor_vehicle/hgv:conditional`
на nodes/ways со значением `no`. Разобранное активное `no` даёт гипотетическое
исключение; неактивное условие не даёт разрешения. Иные значения/неразобранные
условия остаются UNKNOWN; scoped tags, maxheight, relations и другие ключи считаются
отдельно как not modeled. Перекрытие нескольких транспортных областей здесь не
объявляется разрешённым приоритетом: это чувствительность к совокупности гипотез.

## Синтетические сценарии

Все данные сценариев явно имеют `synthetic=true`; источник —
`SYNTHETIC-fixture-only`. Они не смешиваются с реальными ограничениями.

1. Десятичные габариты ниже/равно/выше 4,20 м. Равенство UNKNOWN: запаса нет.
2. Историческая запись, высота самого сооружения, отсутствующие/неизвестные единицы,
   разные значения двух источников — UNKNOWN. Исторический XLSX не обновляется
   предположением о текущем состоянии.
3. Конфликт разрешения/запрета, разрешение легковому при неизвестном HGV,
   ошибка разбора и неполное правило — UNKNOWN.
4. Реальный temporal parser/evaluator: включённое начало, исключённый конец,
   ночь с привязкой к предыдущему дню, PH, повторяющийся и несуществующий час
   Asia/Jerusalem. Разбор/часовая неопределённость не означает разрешение.
5. Реальный turn analyzer: направленная цепочка from/via/to, no/only, except=hgv,
   неполная цепочка и противоположное направление via-way.
6. Исполняемый синтетический граф с памятью последовательности: no блокирует
   полную цепочку, only блокирует иной выход, except=hgv сохраняет путь только
   внутри модели. Барьер и активное временное правило уменьшают достижимость;
   окончание интервала убирает только данное синтетическое ограничение.

Синтетический stateful engine использует атомарный ориентированный way как одно
ребро и ограниченную историю длиной максимальной цепочки минус один. Это не
готовый национальный маршрутизатор: реальные многосегментные ways требуют
проверенных состояний входа/выхода и движения внутри way. Национальное влияние
via-way **NOT IMPLEMENTED**; сценарии no/only исполнены только на явно синтетическом
графе. Нельзя выдавать это за завершённую промышленную маршрутизацию.

## Воспроизведение

```bash
python -m unittest discover -s tests -p test_stage5_scenarios.py -v
python -m scripts.stage5.scenarios /absolute/original/graph.sqlite connectivity.json --rules rules.json
```

`rules.json` содержит `node_rules`, `way_rules`, при необходимости `temporal_records`.
Нормализованное правило: `id`, `decision` (TAGGED_DENIED/UNKNOWN/TAGGED_ALLOWED),
`direction` (forward/backward/both). RESTRICTED при адаптации остаётся UNKNOWN.
Оригинальные источники/обоснования сохраняются в первичных реестрах этапа 5;
сводка связности не заменяет эти реестры.

Основной интеграционный runner передаёт фактические barrier/HGV/temporal records
и повторяет генерацию. Итоговые числа и контрольные суммы берутся из результатов
последнего полного интеграционного запуска, а не из исторического документа.
