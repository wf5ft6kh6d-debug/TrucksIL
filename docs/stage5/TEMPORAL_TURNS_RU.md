# Этап 5: исследовательские временные условия и повороты

Все выходные записи имеют `status=QUARANTINE`, `navigation_eligible=false`.
`parse_status=SUPPORTED` означает только принадлежность реализованному подмножеству;
это не подтверждение дорожного знака, законности или безопасности проезда.
Исходные теги, участники, источник, идентификатор объекта и имя тега сохраняются.
Точный переданный пользователем текст временных ограничений недоступен этому
исполнителю. Он не реконструировался по памяти и не заменялся синтетическими правилами.

## Поддерживаемое время

`value @ (Mo-Fr HH:MM-HH:MM)`, один день недели либо ежедневный интервал
`value @ (HH:MM-HH:MM)`. День недели ISO; диапазон может переходить через воскресенье.
Начало включено, конец исключён. `24:00` допустимо только в конце.
Интервал через полночь относится к дню начала, включая хвост следующего дня.
Равные начало/конец неоднозначны и не поддерживаются.
Числовое value — только сохранённый текст значения; парсер не устанавливает единицы.
Списки условий, праздники PH/SH, даты, солнечное время и иные выражения не поддержаны.

Оценка требует aware datetime; момент переводится в `Asia/Jerusalem` через IANA
`zoneinfo`. Неоднозначный час осеннего перехода в обеих реализациях fold даёт
UNKNOWN, даже если входной UTC-момент различает два вхождения. Несуществующее
весеннее локальное время, переданное как ZoneInfo datetime, также UNKNOWN.
Это намеренное ограничение поддерживаемого подмножества, а не утверждение о
юридическом действии запрета в переходный час. `active=false` означает только,
что конкретное распознанное условие не активно; это НЕ разрешение движения.

## Повороты

Поддерживаются перечисленные no/only left/right/straight/u_turn. Выбор поля:
`restriction:hgv`, затем `restriction:motor_vehicle`, `restriction:vehicle`,
`restriction`. Поле для motorcar не переносится на HGV. Наследуемые conditional
в другом транспортном scope, неизвестные квалификаторы и конфликт обычного и
условного значений требуют карантинного разбора, дают parse_status UNKNOWN.
`except` сохраняется; известны hgv/motor_vehicle/vehicle/bus/bicycle/motorcar/
taxi/psv/emergency/motorcycle. Исключение HGV или его классов меняет только
`applies_to_hgv`; специфичное HGV-правило с противоречащим except — UNKNOWN.

Требуются ровно один from-way и to-way, один via-node либо упорядоченные via-ways.
Порядок via сохраняется из отношения, не угадывается. Максимум 64 ways в цепочке.
Каждая пара соседей должна иметь ровно один общий OSM node ID; геометрическое
пересечение и snapping не используются. Проверяется подход from, проезд каждого
via от входа к выходу и выход to с учётом явного oneway yes/no/-1 (и синонимов).
Любые квалификаторы `oneway:*` (включая conditional и hgv) не поддержаны и
сохраняют направление UNKNOWN, даже при явном базовом oneway.
Отсутствующий oneway остаётся UNKNOWN, даже для motorway/roundabout.
Повторные ways, повторные узлы, кольца, несколько общих узлов, смешанные via,
пропущенные ссылки и конфликт направлений остаются UNKNOWN. Поэтому многие
реальные развороты с from=to сознательно не входят в подмножество.

NO_SEQUENCE/ONLY_SEQUENCE — декларация разобранного типа, не готовый маршрутный
автомат. Запрет относится ко всей цепочке; ONLY требует состояния префикса, его
нельзя применять как запрет одного ребра. Направление left/right геометрически
не подтверждается; код проверяет топологию, а не правильность знака.

## API и воспроизведение

- `parse_conditional(raw, source=None)` и `evaluate_conditional(record, instant)`.
- `analyze_turn(tags, members, ways, source=None, vehicle='hgv')`.
- `iter_temporal_records(sqlite_connection, source)` читает ways/relations/candidates,
  сохраняет все conditional tags с дедупликацией по типу/id/имени тега.
- `iter_turn_records(sqlite_connection, source)` читает все отношения, извлекает
  участники через индекс id, сохраняя ограниченную память одной цепочки.

Исходная SQLite передаётся read-only; выходы создаются отдельно. Реальные записи
и синтетические тесты не смешиваются. Проверка:

```sh
python -m unittest discover -s tests -p 'test_stage5_temporal.py' -v
python -m unittest discover -s tests -p 'test_stage5_turns.py' -v
```

37 профильных регрессионных тестов выполнены успешно до интеграции. В их числе
полночь, границы интервалов, DST, неполные/неоднозначные цепочки, направления,
приоритет HGV, исключения, неподдержанные условия и конфликты base/conditional.
Национальные числа и окончательная приёмка фиксируются интеграционным прогоном;
результаты этого модуля не меняют число VERIFIED, оно остаётся нулевым.
