# Stage 5 — интеграция исследовательских правил

Исходные миграции `db/stage2.sql` и `db/migrations/0002_closed_ingest.sql`
прочитаны. Закрытый эксплуатационный ingest не изменяется. Новый SQL создаёт
только транзакционную схему `trucksil_stage5_test` в одноразовой БД с именем
`trucksil_stage5_test_*`, через локальный Unix socket. Проверка имени БД и
отсутствия сетевого адреса выполняется до создания расширения или схемы.
Production и существующая схема не затрагиваются.

## Контракт

`data/stage5/research.schema.json` — закрытый исследовательский конверт:

- идентичность записи, вид и источник с SHA-256;
- исходный payload, неизменённый результат специализированного обработчика;
- объяснение и доказательный статус только QUARANTINE / UNKNOWN;
- `navigation_eligible=false` без исключений;
- `synthetic` и соответствующий тип источника должны совпадать;
- допустимая GeoJSON Point / LineString в WGS84 либо отсутствие геометрии.

Разрешающий OSM-тег и поддержанный синтаксис не меняют доказательный статус.
`UNKNOWN` внутри `interpretation` отделён от статуса доказательств. Реальные
записи считаются в `research.jsonl`, синтетические — отдельно в
`synthetic-scenarios.jsonl`. Число записей включает node-way incidences и отдельные
conditional-теги; это не количество уникальных физических ограничений.

## Воспроизведение

Из корня репозитория с зависимостями, закреплёнными в workflow:

```bash
python -m unittest discover -s tests -v
python scripts/compare_schema_engine.py
python scripts/stage5/run_research.py PATH/graph.sqlite PATH/israel-and-palestine-261008.osm.pbf OUTPUT --repeat
```

Выходная папка должна отсутствовать. Проверяется SHA-256 PBF по исходному
manifest этапа 4. Исходная SQLite открывается read-only. Хеши обоих источников
сверяются до и после. Повтор создаёт `OUTPUT-repeat`; сводка и хеши каждого
JSONL, JSON и SQL должны точно совпасть.

Полные независимые проверки сверяют все исходные барьерные узлы PBF, записи
ways, вхождения узлов, conditional и turn payload. Поддержанные цепочки
поворотов дополнительно проходятся независимым алгоритмом по явным направлениям.

`stage5-postgis.sql` выполняется только в одноразовой БД:

```bash
psql -X -h /var/run/postgresql -d trucksil_stage5_test_national -v ON_ERROR_STOP=1 < OUTPUT/stage5-postgis.sql
```

SQL включает полную загрузку, внешние ключи, ограничения статусов и JSON,
пространственный GiST, сопоставление каждой записи, повторный импорт без
повторных событий аудита, отклонение конфликтующей идентичности, аудит
изменений и запрет изменения журнала, негативные проверки отсутствующих/null
полей, запрет VERIFIED/разрешения навигации проверку неизменности источника и совпадения геометрии с payload, и итоговый rollback. После rollback
проверяется отсутствие тестовой схемы. Только фактический маркер
`STAGE5_POSTGIS_PASS` свидетельствует об исполнении; наличие файла не означает PASS.

## CI

`.github/workflows/stage5-national.yml` запускается при push в новую ветку.
Сохранены все национальные этапы 4: исходник, все сегменты, независимые проверки,
пять производных слоёв, точный повтор, полные PostGIS проверки исходного графа,
границ, геометрии и инфраструктуры. Затем проверяются новые исследовательские
слои и SQL. Таймаут 120 минут учитывает повторную национальную обработку;
это не замена проверки выборкой.

Унаследованный workflow получил только дополнительную ветку push и зависимость
osmium для полного нового набора тестов. Ни одна старая проверка не удалена.
Фактические результаты запусков, проверенный SHA и ссылки — в итоговом отчёте.

## Ограничения

- Пользовательский XLSX не публикуется в Git или артефактах публичного CI.
  Реальная нормализация и оригинал сохраняются отдельно; здесь выполняются
  только явно синтетические workbook-тесты.
- Оригинальный текст временных ограничений не реконструируется из пересказа.
- Национальная связность показывает чувствительность к барьерам/access и
  неопределённости. Для temporal вычисляются два явно исследовательских национальных среза
  12 октября 2026 в 07:00 и 09:00 Asia/Jerusalem. Via-way правила требуют
  истории переходов; национальный state-expanded routing пока отсутствует.
- Три фиксированные BFS-точки не являются полной all-pairs проверкой.
- Подтверждённых действующих грузовых ограничений 0. Полнота дорог и безопасность
  маршрутизации не доказаны.
