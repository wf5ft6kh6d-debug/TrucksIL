# Этап 5 — node barriers и явные правила HGV

Модуль `scripts/stage5/barriers.py` создаёт отдельный исследовательский слой. Все исходные объекты остаются `QUARANTINE`, `navigation_eligible=false`; физическая проходимость — `UNKNOWN`. Интерпретация тега не является подтверждением действующего ограничения.

## Поддерживаемая модель

Приоритет вида транспорта: `hgv > motor_vehicle > vehicle > access`. Внутри выбранного вида транспорта значение `:forward` / `:backward` для рассматриваемого направления имеет приоритет над общим значением. Направления соответствуют порядку узлов исходного way. `motorcar` не входит в эту иерархию для грузовика.

`no` даёт `TAGGED_DENIED`; `yes`, `permissive` и транспортно-специфичный `designated` дают `TAGGED_ALLOWED`. `private`, `destination`, `delivery`, `customers`, `permit`, `agricultural`, `forestry` дают `RESTRICTED`: необходимы сведения о разрешении или цели поездки. Общий `access=designated`, отсутствующие и неизвестные значения дают `UNKNOWN`.

Любые conditional, неизвестные модификаторы и `except` сохраняются целиком и дают `UNKNOWN`. Это сознательно консервативная граница реализации: отдельный временной обработчик не превращает такой объект автоматически в разрешение. На узле направленные теги дают `UNKNOWN`, поскольку порядок incident ways не устанавливает однозначного направления самого барьера.

Ворота, столбики и другие `barrier=*` сохраняются без предположений о том, открыты ли они, убираются ли и достаточен ли физический габарит. Даже `barrier=no` без access не даёт разрешения. Way и узел накладывают независимые условия: явные противоположные указания дают конфликт/`UNKNOWN`, отдельный запрет при неизвестности другого элемента сохраняется как `TAGGED_DENIED`, неразрешённая неизвестность не очищается разрешением way.

## Источники семантики

Первичная документация OSM, прочитана 12 октября 2026:

- https://wiki.openstreetmap.org/wiki/Key:access — иерархия режимов транспорта, отдельные условия доступа.
- https://wiki.openstreetmap.org/wiki/Key:motor_vehicle — охват моторных транспортных средств, включая HGV.

Это источники **значения OSM-тегов**, а не официальные доказательства дорожных правил Израиля. Не применяются национальные умолчания доступа и физические умолчания барьеров.

## Воспроизведение

```bash
python scripts/stage5/barriers.py INPUT.osm.pbf SOURCE/graph.sqlite NEW_OUTPUT_DIRECTORY --manifest data/stage4/national-source-manifest.json
python -m unittest discover -s tests -p test_stage5_barriers.py -v
```

`build(pbf, source_sqlite, outdir, manifest)` проверяет SHA-256 PBF, читает SQLite `mode=ro`, отказывается перезаписывать каталог и повторно проверяет хеши обоих исходников. Извлечение узлов выполняется из полного PBF, поскольку исходная таблица nodes не содержит тегов.

Выходные файлы:

- `barrier-nodes.jsonl`: все узлы с barrier либо релевантными access/HGV-тегами, включая узлы вне highway ways; исходные ID, версии, timestamps, координаты, теги и решение.
- `way-access.jsonl`: highway ways с релевантными access/barrier-тегами; решения отдельно для forward/backward.
- `node-way-access.jsonl`: каждое вхождение исходного node ID в way, включая повторные вхождения; исходная позиция и совмещённые решения. Геометрические пересечения не создают связи.
- `summary.json`: счётчики, provenance, SHA-256 каждого JSONL, сохранность исходников. Счётчики статуса относятся к уникальным source objects; incidence — отдельные записи, а не новые ограничения. `UNKNOWN` интерпретации считается отдельно от статуса доказательства.

Все JSONL сортируются детерминированно по ID объектов/порядку исходных узлов; поля JSON также сортируются. Тесты явно маркированы как синтетические, включают исходное извлечение, повторную генерацию, сохранность SQLite, неопределённые и конфликтующие правила. Они не смешиваются с реальными дорожными свидетельствами.

Не реализованы: физический габарит ворот, состояние замка, персональные разрешения, вывод о доступности на основании `motorcar`, применение ограничений к эксплуатационной навигации. Отсутствие записи либо тега означает недостаток сведений.
