## Контракт данных

`scripts/stage6/contract.py` и `data/stage6/research.schema.json` задают закрытый
конверт `stage6.research.v1`: идентификатор, тип записи, источник и SHA-256,
исходный payload, результат интерпретации, объяснения, геометрия либо null,
явная маркировка синтетики. Доказательный статус допускает только QUARANTINE
или UNKNOWN. `navigation_eligible` всегда false. Результат исследовательского
маршрутизатора (найден путь, нет пути, неопределённость, исчерпаны ресурсы)
сохраняется отдельно в `interpretation` и не изменяет доказательный статус.

Реальные OSM-эксперименты и синтетические сценарии сохраняются в разных JSONL
и импортируются отдельными SQL. `generate()` запрещает смешанный импорт,
перезапись исходника и существующего SQL. Реальные приватные bridge/claim
реестры не входят в публичный runner, Git или CI. Их количества и статусы
должны учитываться в итоговом отчёте отдельно; синтетические фикстуры не
подменяют реальные сведения.

Новая схема дополнительно сверяется двумя движками: существующим локальным
валидатором и Draft202012Validator на ограниченном корпусе из 38 случаев;
это не заявление полной conformance. Старые 54 сравнения сохранены.

## Воспроизведение

```bash
python -m unittest discover -s tests -v
python scripts/compare_schema_engine.py
python scripts/stage6/contract.py
python scripts/stage6/run_research.py GRAPH.sqlite SOURCE.osm.pbf /tmp/trucksil-stage6-output --repeat
```

Выходные каталоги должны отсутствовать. Runner проверяет зафиксированный SHA
источника PBF, сохраняет хеши PBF/SQLite до и после, вызывает национальный
ограниченный эксперимент и независимые синтетические сравнения. Все
обязательные артефакты перечислены явно: временные файлы синхронизации не входят
в manifest; отсутствие обязательного файла вызывает отказ. Повторная
генерация должна совпасть по сводке и всем обязательным SHA-256. Наблюдаемое
время исполнения и RSS выводятся как STAGE6_PERFORMANCE в stderr; CI сохраняет
их отдельно в evidence/stage6-performance.log. Телеметрия не подменяет
воспроизводимые статусы, пути и счётчики сценариев.

## PostgreSQL / PostGIS

SQL принимает только локальный Unix socket и имя базы
`^trucksil_stage6_test_[a-z0-9_]+$`, проверяя их до создания расширения/схемы.
Для CI используется одноразовый контейнер PostgreSQL 16.4 / PostGIS 3.4.3 с
закреплённым digest, `--network none`, без опубликованных портов.

```bash
psql -X -h /var/run/postgresql -d trucksil_stage6_test_national -v ON_ERROR_STOP=1 < /tmp/trucksil-stage6-output/stage6-postgis.sql
psql -X -h /var/run/postgresql -d trucksil_stage6_test_national -v ON_ERROR_STOP=1 < /tmp/trucksil-stage6-output/stage6-synthetic-postgis.sql
```

Сохранены проверки целостности всех строк, источников и FK; неизменности
реестра источников; соответствия geometry/JSON; запрета VERIFIED и разрешения
навигации; GiST; повторного импорта без дублирующих событий; аудита old/new;
отклонения отсутствующих/null/лишних полей, нестроковых reasons, неправильных
типов/форматов source и подмены provenance; rollback и отсутствия
оставшейся схемы. SQL контролирует критический конверт и provenance напрямую, а не полагается
только на Python. Произвольное содержимое raw/interpretation не имеет
универсальной предметной схемы; его семантику проверяют профильные обработчики
и независимые сценарии. Полная эквивалентность SQL и JSON Schema не заявляется.
Наличие SQL не означает выполнение. Фактический маркер
успеха каждого запуска — `STAGE6_POSTGIS_PASS`.

## Обязательные CI gates

1. Полный актуальный unittest-набор без удаления старых проверок; старые 54
   сравнения схем и новые 38.
2. Ранняя синтетическая SQL-проверка до длительной обработки.
3. Зафиксированный PBF, полная генерация исходного национального графа,
   независимая проверка его строк, исходный национальный PostGIS acceptance.
4. Stage 6 национальный ограниченный эксперимент и синтетический независимый
   oracle, точная повторная генерация, отдельные реальные/синтетические
   PostGIS импорты и rollback.
5. Унаследованный workflow: пилот Хайфы, миграции, журнал, отрицательные
   checksum/неверсионированная схема/failure-rollback проверки.

Повторный пространственный анализ 948 914 пар этапа 4 не включён в новый
workflow: его алгоритмы/исходные данные не изменяются, а точная база уже прошла
национальную приёмку этапа 5. Старые тесты этого кода остаются в полном наборе;
старые workflow не изменены. Это обоснованное исключение повторного дорогого
прохода, а не удаление или ослабление прежних тестов.

## Ограничения результата

Наличие исследовательского пути не означает разрешение или безопасность HGV.
Национальный эксперимент ограничен заявленными сценариями и ресурсными
лимитами; исчерпание бюджета должно давать INCOMPLETE с причиной. Ограничения
не отбрасываются ради нахождения пути. Национальная полнота не заявляется.
Числа фактически проверенных записей, результаты и окончательный SHA/ссылки
CI фиксируются в итоговом отчёте после выполнения, не заранее.
