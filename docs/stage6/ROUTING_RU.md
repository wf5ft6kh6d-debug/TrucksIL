# Stage 6: ограниченная исследовательская маршрутизация с историей

Код: `scripts/stage6/routing.py`. Исходные Stage 5 не изменяются.
Все результаты имеют `navigation_eligible=false`; ни один статус не является
доказательством действующего ограничения или разрешением грузового проезда.
Это модельный эксперимент на переданных рёбрах, свидетельствах и предположениях.

## Контракт

```python
research_route(edges, start, goal, rules, departure, limits=None, vehicle='hgv')
```

Ребро — реальный направленный сегмент, а не атомарная way:
`id`, `from`, `to`, `way_id`, `duration_seconds`, `direction_status`, `admissibility`.
Идентификаторы — строки или целые числа. `direction_status=KNOWN` означает
направление дуги в исследовательской модели; UNKNOWN/отсутствие означает
неопределённость, BLOCKED исключает дугу. Это не достоверность дорожного источника.
`admissibility=KNOWN/UNKNOWN/DENIED` — отдельный результат переданной политики
барьеров/габаритов/доступа. Отсутствие поля означает UNKNOWN. Политика не может
молчаливо выдавать KNOWN при отсутствии свидетельств. Для контрольного графа
с намеренно отключённым слоем ограничений допущение отмечается явно вне роутера.
Причины неизвестности рёбер передаются в `reasons`.

Длительность — явно заданное исследовательское предположение. Положительные
конечные секунды используются как время движения; отсутствующее, неположительное
или непредставимое значение делает время последующей цепочки неизвестным.
Роутер не угадывает скорость по классу дороги и не подменяет неизвестное время
известным нулём: ноль применяется лишь как технический приоритет неизвестной
ветви, а `arrival=None` и неопределённость сохраняются до результата.

Правило: `id`, `sequence` — упорядоченные way ID, `connection_nodes` — узлы
переходов длиной len(sequence)-1, `kind=no/only`, `parse_status`, `except`,
опционально `conditional` — запись парсера Stage 5. Поддерживаются также поля
Stage 5 `chain_way_ids`, `connection_node_ids`, `semantics`.
Сохранённый UNKNOWN не повышается до SUPPORTED. Если исходное Stage 5 содержит
обычный базовый restriction, его действие не исчезает вне conditional-интервала.
Неразрешённый конфликт базового/условного правила остаётся UNKNOWN из Stage 5.

## Состояние и последовательности

Состояние содержит узел, суффикс run-истории `(way_id, entry_node)`, предыдущую
направленную дугу, флаг неопределённости и, для временных правил, фактическое
прошедшее время. Обычная проверка «посещён ли узел» недопустима: возвращение в
тот же узел с иной историей может менять применимость ограничения.

Run объединяет последовательные сегменты одной way, включая обратное движение
по этой way. Это сохраняет исходный вход в via-way: разворот внутри неё не
стирает префикс from/via и не обходит запрет. Непосредственный возврат по предыдущей
дуге отдельно распознаётся как разворот для `sequence=[A,A]` и ONLY-проверок.
Длинные цепочки с подряд повторённой way неподдержаны и дают UNKNOWN; повторение
way через другие ways и повторное посещение узлов сохраняются в порядке движения.

NO проверяется при завершении всей последовательности в точном узле соединения.
ONLY активируется в указанном узле перехода from; преждевременный уход с from
до этого узла сам по себе не запрещён данным правилом. После входа в via запрещён
уход на другую way до следующего указанного перехода. В указанном узле нельзя
обойти ONLY, продолжив движение по той же way. Продолжать via между переходами
можно. При совпадении нескольких префиксов проверяются все обязательства.
Вход на ту же via-way из другой from или другого соединительного узла не создаёт
чужое обязательство. Геометрическое пересечение не образует узел, snapping нет.

Исключения HGV/motor_vehicle/vehicle влияют только на SUPPORTED-правила;
неподдержанное исключение не трактуется как освобождение. UNKNOWN-правило
влияет на переходы, касающиеся перечисленных ways; отсутствие корректной
области действия консервативно влияет на все переходы. Правила не удаляются ради
нахождения пути.

## Время

Условие оценивается в момент прибытия к манёвру, ПЕРЕД прохождением следующего
сегмента. Не используется время старта всего маршрута. Время считается в UTC;
парсер Stage 5 переводит момент в Asia/Jerusalem. Начало интервала включено,
конец исключён, полночь привязана к дню начала. Неоднозначный осенний час,
несуществующее весеннее локальное время, неподдержанный календарь и неизвестное
время не дают разрешения: результат перехода UNKNOWN.

Действие ожидания отсутствует. При временных правилах один и тот же узел/история
в разное время — разные состояния; циклы могут изменять время прибытия. Поэтому
поиск обязательно ограничен ресурсами, а исчерпание бюджета не равняется
отсутствию маршрута. Начало=конец допускает пустой исследовательский путь с
сохранением неопределённости входного времени; это не проверка площадки стоянки.

## Ограничения ресурсов

До национальных экспериментов фиксируются бюджеты:

| Параметр | По умолчанию |
|---|---:|
| max_states | 100 000 |
| max_memory_bytes | 134 217 728 |
| max_runtime_seconds | 30 |
| max_input_edges | 500 000 |
| max_expansions | 500 000 |
| max_rules | 50 000 |
| max_rule_length | 64 |

Нет автоматического увеличения лимитов. Превышение входного размера, длины
правила, времени, количества состояний/переходов или памяти возвращает INCOMPLETE
с конкретной причиной. Частично прочитанный граф/набор правил не исследуется
как будто он полный.

`accounted_memory_bytes` — консервативный учёт удерживаемых объектов через
`sys.getsizeof`, с повторным учётом общих подструктур и накладными резервами.
Это НЕ RSS и не глобальный лимит ОС. Национальный исполнитель должен использовать
изолированный процесс и отдельный OS hard limit (например RLIMIT_AS), сообщая его
отдельно; превышение такого лимита также не является NO_ROUTE. Детерминированность
этого счётчика требует одинаковой версии/разрядности Python. Измеренные wall time
и RSS записываются исполнителем отдельно от воспроизводимого результата.

## Статусы

- RESEARCH_PATH_FOUND: найден путь без обнаруженной модельной неопределённости.
  Это НЕ VERIFIED и НЕ разрешение проезда.
- ADMISSIBILITY_UNDETERMINED: найден только путь с неизвестностью; возвращаются
  его edge IDs и причины. Неизвестный путь не объявляется допустимым.
- NO_ROUTE: поиск исчерпан в переданной модели без подходящего пути; это не
  утверждение об отсутствии физического маршрута на всей дорожной сети.
- INCOMPLETE: ресурсный или структурный блокер; отрицательный вывод запрещён.

Сначала исследуются пути без неопределённости, затем неизвестные; длина сравнивается
внутри этой очередности. Поэтому алгоритм не обещает кратчайший физический маршрут
среди путей с разной достоверностью. При неизвестной длительности оптимальность
по реальному времени вообще не утверждается.
