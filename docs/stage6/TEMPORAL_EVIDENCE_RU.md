# Этап 6: происхождение временных утверждений

Проверка 12 октября 2026 года. Технический реестр подготовлен; доказанность действующих ограничений **BLOCKED**. В приватном реестре 11 атомарных утверждений: QUARANTINE 11, VERIFIED 0. Оригинал пользователя, его адрес сообщения, дата, SHA-256, точные выдержки и связи с утверждениями находятся вне Git. Этот документ не воспроизводит пользовательский текст.

`scripts/stage6/claims.py` хранит исходные Unicode-срезы `[start,end)` без перефразирования и без автоматического разбора в маршрутные правила. Каждое поле имеет точную связь с символами своего утверждения. Неуказанные параметры остаются `null`; заголовочная масса не переносится автоматически в соседние пункты. Прежнее подтверждение пользователя записано только как свидетельство пользователя. Номера сносок не считаются внешними доказательствами.

Во всех 11 утверждениях отсутствуют дни действия и даты вступления/окончания действия; направление не установлено из собственного текста в 8, масса — в 9. Это подсчёт явных полей атомарных утверждений, а не заключение о реальных дорожных правилах. Связь пунктов с общим заголовком не используется для восполнения неизвестных параметров. Неопределённые выражения времени сохраняются текстом; границы дня и исключения не додумываются.

Обнаружено различие временного охвата в материалах об опасных грузах: более общий запрет оператора совместим с запретом днём, поэтому это **scope mismatch**, а не доказанное логическое противоречие и не основание объявлять пользовательское утверждение ложным. Кроме того, найден вторичный исторический указатель на изменение вечернего интервала; он сохранён отдельно как повод искать официальный акт, без исправления пользовательского исходника и без использования как доказательства действующего правила.

Поиск проведён двумя движками и прямым чтением документов. Некоторые запросы основного движка возвращали нерелевантные результаты; это ограничение поиска, а не доказательство отсутствия ограничений. Исследование не заявляет исчерпывающий охват всех официальных реестров.

## Проверка и последующий шаг

```bash
python -m unittest discover -s tests -p test_stage6_claims.py -v
python scripts/stage6/claims.py PRIVATE_REGISTRY.json
python scripts/stage6/claims.py PRIVATE_REGISTRY.json --summary
```

16 синтетических тестов проверяют дословность, Unicode-offsets, запрет выдуманных полей, неизменность входов, отсутствие повышения статуса и приватных данных в агрегированной сводке. API: `build_registry(text, specifications, source)`, `validate_registry(registry)`, `public_summary(registry)`. Последний экспортирует только закрытый набор агрегатов; приватный реестр не входит в публичный CI.

Следующий шаг: получить точные действующие приказы/реестр знаков с датой, участком, направлением, разрешённой полной массой, расписанием и исключениями, затем провести независимую сверку. Текущие результаты нельзя применять как подтверждённые ограничения эксплуатационной навигации.
