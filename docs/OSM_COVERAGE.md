# Покрытие OSM: ограничения для грузовиков (Израиль)

> **Статус:** измерено 14.11.2026 на выгрузке Geofabrik (запуск скрипта локально владельцем проекта, ~53 с).

## Данные

- Источник: Geofabrik, `asia/israel-and-palestine-latest.osm.pbf`
  (покрывает Израиль, Западный берег и Газу).
- Дата данных: самый свежий объект `2026-11-13T21:02:35Z` (≈ момент среза).

## Метод

```
pip install osmium
python3 scripts/osm_coverage.py israel-and-palestine-latest.osm.pbf > osm_result.json
```

Скрипт (`scripts/osm_coverage.py`) выводит только агрегаты:

- учитываются way с `highway=*`, кроме пешеходных/вело/строящихся;
  `*_link` относятся к родительскому классу;
- счётчики тегов для way и node: `maxheight`, `maxheight:physical`, `maxwidth`,
  `maxlength`, `maxweight`, `maxaxleload`, `hgv`, `hazmat`;
- `bridge`/`tunnel`/`covered` (≠ `no`) на дорогах: всего и сколько из них имеют
  `maxheight` или `maxheight:physical`;
- разбор `maxheight`: метры, число без единицы, футы/дюймы (`14'6"`), `ft`,
  нечисловые (`default`, `none`, `below_default`…); корзины < 2 м … > 7 м.

Ограничения метода:

- `maxheight` на way-мосте относится к проезду **по** мосту; габарит **под**
  мостом ставится на нижнюю дорогу (или на node). Скрипт не делает
  геометрического сопоставления «мост → дорога под ним», поэтому доля мостов с
  `maxheight` — нижняя оценка полезного покрытия. Для туннелей и `covered`
  оценка корректна.
- Разделение Израиль / Западный берег / Газа — по первой точке way и грубым
  полигонам в скрипте. Это не юридическая граница; Иерусалим и шовная зона
  классифицируются неточно. Использовать только для порядка величин.

### Что это значит

- **Покрытие очень низкое.** Высота указана у 0,17 % дорожных way. У мостов почти нет (9 из 3 040), но это ожидаемо: габарит под мостом ставят на нижнюю дорогу, скрипт это не сопоставляет. Лучше всего покрыты туннели (14 %) и автомагистрали (6 %).
- **Половина значений ≥ 5 м** — скорее всего это габариты развязок и туннелей на магистралях, для грузовика обычно не критичные. Опасные низкие габариты (2–4 м, 113 значений) встречаются редко и в основном на мелких дорогах и парковках (не проверено).
- **Весовых и прочих грузовых ограничений в OSM почти нет** (maxweight 77, hgv 16, hazmat 0). Для этих ограничений OSM не источник.
- 4 значения < 2 м и 10 > 7 м — вероятные ошибки разметки или въезды в паркинги; проверять перед использованием.
- Итог: OSM годится как редкий набор кандидатов и для проверки покрытия, но **не заменяет официальный слой мостов Минтранса**.

## Выводы для TrucksIL

- Значения из OSM — только **кандидаты** (`status: unverified`). Без подтверждения
  знаком или официальным источником `valueSource` = `unknown`; `posted_sign` —
  только если известно, что значение снято со знака (например, есть
  `source:maxheight=sign` или фото/обход).
- Нечисловые значения (`default`, `none`, `below_default`) не дают габарита и
  не должны превращаться в число.
- Выбросы (< 2 м, > 7 м) и значения в футах — отдельная проверка перед импортом.
- Отсутствие тега ≠ отсутствие ограничения; маршрутизация не должна считать
  мост без `maxheight` безопасным.

## Габарит под мостами: `scripts/osm_bridge_clearance.py`

В OSM габарит под мостом ставится на дорогу, проходящую **под** мостом
(`maxheight`/`maxheight:physical` на way или на узле), а не на сам мост, поэтому
«9 мостов с maxheight из 3040» недооценивает покрытие. Скрипт ищет такие
проезды под мостами и считает, у скольких есть габарит.

Запуск (локально, в venv с `pip install osmium`):

```
python3 scripts/osm_bridge_clearance.py israel-and-palestine-latest.osm.pbf > bridge_clearance.json
```

Тесты геометрии (osmium не нужен):
`python3 -I -m unittest discover -s scripts -p 'test_osm_bridge_clearance.py'`.

Вывод — только агрегаты JSON: число мостов над дорогами (автомобильные и
ж/д отдельно), число проездов под мостами (пар мост×дорога), сколько из них
с габаритом (тег на way или узел с `maxheight` в пределах 30 м от пересечения),
разбивка по классу дороги снизу, распределение высот, дата данных (макс. timestamp).

Ограничения метода:

- Пересечение ищется в 2D по отрезкам; общий узел = примыкание, а не проезд снизу.
  Дорога считается «под мостом», только если её `layer` меньше слоя моста
  (по умолчанию дорога 0, мост 1). Ошибочные `layer` дают пропуски/ложные пары.
- Мосты: `highway=*` + `bridge≠no`, ж/д — только `bridge=yes`. Дороги снизу —
  без footway/path/cycleway/steps/construction/proposed и без `tunnel`/`covered`.
  Реки, долины, ж/д пути под мостом не учитываются.
- Габарит на way относится ко всему way, не обязательно к этому мосту; узел
  в 30 м может относиться к соседнему сооружению. Дорога, проходящая под
  несколькими мостами, считается в каждой паре.
- Длинный мост над несколькими дорогами даёт несколько проездов; параллельные
  проезжие части одной дороги считаются отдельно.
- Ways без координат на границе выгрузки пропускаются. Результат — оценка
  покрытия, а не перечень габаритов; значения остаются `unverified`.

**Выводы:**
